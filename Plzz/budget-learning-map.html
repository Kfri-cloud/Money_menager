인스턴스는 특정 클래스로 만든 객체라는 뜻이다. 두 거래는 같은 타입이어도 담긴 값이 다르다.

메서드는 클래스에 정의된 함수다. self라는 단어 자체가 예약어는 아니지만 관례를 지킨다.

생성 과정과 __init__개발자 설명 열기

Class(...) 호출은 인스턴스를 생성하고 초기화한다. 엄밀히 __new__가 생성을 담당하고 __init__은 생성된 인스턴스를 초기화한다. __init__은 None을 반환해야 한다.

가계부 코드에서 보는 형태

def __init__(self, repository):

새 공책을 만들고 첫 장에 주인과 용도를 쓰는 초기 준비 과정이다. 가계부에서는 사용할 저장소를 기억하게 한다.

생성자라는 말을 __init__에 흔히 쓰지만 정확히는 초기화 메서드다. 이 과제에서는 __new__를 직접 구현할 필요가 없다.

타입 힌트와 반환값개발자 설명 열기

타입 힌트는 매개변수와 반환값의 기대 타입을 표현한다. return은 호출자에게 값을 전달하고 함수 실행을 끝낸다. return이 없으면 None이다. print는 화면 출력이며 반환과 다르다.

함수는 작업을 받아 결과를 돌려주는 작은 작업실이다. 타입 힌트는 주문서에 적힌 “정수를 넣고 정수를 받으세요”라는 안내다.

-> int는 결과가 정수라는 계약이다. 힌트를 적는 것만으로 Python이 모든 입력을 검사하지는 않는다.

거래 기록의 빈칸들이 필드다. 날짜 칸, 금액 칸, 메모 칸처럼 한 거래를 설명하는 정보를 담는다.

@dataclass의 역할개발자 설명 열기
LEVEL 2 · 개발자 관점

dataclass는 주석으로 선언한 필드를 바탕으로 __init__, __repr__, __eq__ 등을 기본 생성한다. 정렬 비교는 기본 제공이 아니며 order=True 같은 설정이 필요하다. CSV 변환이나 유효성 검증은 자동 제공하지 않는다.

가계부 코드에서 보는 형태

from dataclasses import dataclass

@dataclass
class Category:
    name: str
한 번 더 들어가기 · 쉬운 풀이와 단어 설명
LEVEL 3 · 중·고등학생 눈높이

매번 손으로 만드는 초기화·내용 표시·같은 값인지 비교하는 코드를 대신 작성해 주는 도우미다.

__repr__는 개발자가 객체 내용을 살펴볼 때 쓰는 문자열 표현이고, __eq__는 == 비교 동작이다.

필수 필드와 기본값개발자 설명 열기
LEVEL 2 · 개발자 관점

기본값 없는 필드는 생성 시 전달해야 한다. 기본값 있는 필드는 생략 가능하다. 일반적인 dataclass 선언에서는 기본값 없는 필드를 먼저 배치한다.

가계부 코드에서 보는 형태

@dataclass
class Note:
    category: str
    memo: str = ""
한 번 더 들어가기 · 쉬운 풀이와 단어 설명
LEVEL 3 · 중·고등학생 눈높이

이름은 꼭 적고 메모는 안 적어도 빈칸으로 두는 신청서와 같다. 생략 가능하다는 것이 None을 허용한다는 뜻은 아니다.

Note("식비")는 memo에 빈 문자열을 쓴다. Optional 또는 str | None은 별개로 None도 값으로 허용한다는 뜻이다.

default_factory와 변경 가능한 값개발자 설명 열기
LEVEL 2 · 개발자 관점

기본값은 일반적으로 클래스 정의 시 평가된다. 변경 가능한 객체를 공유하면 한 객체의 수정이 다른 객체에 영향을 줄 수 있다. field(default_factory=list)는 인스턴스마다 새 리스트를 만든다. 현대 dataclass는 흔한 변경 가능 기본값을 선언 단계에서 거부한다.

가계부 코드에서 보는 형태

from dataclasses import field

tags: list[str] = field(default_factory=list)
한 번 더 들어가기 · 쉬운 풀이와 단어 설명
LEVEL 3 · 중·고등학생 눈높이

여러 학생이 같은 공책 한 권을 나눠 쓰면 서로의 기록이 섞인다. default_factory는 학생마다 새 공책을 한 권씩 나눠 준다.

factory는 새 값을 만드는 함수다. list()를 미리 호출한 결과가 아니라 list 자체를 넘겨 필요할 때 호출하게 한다.

데이터 구조와 런타임 검증개발자 설명 열기
LEVEL 2 · 개발자 관점

Transaction(amount=-1) 같은 값은 타입이 int라는 사실과 양수라는 규칙이 다르다. dataclass와 힌트만으로 양수·등록 카테고리·날짜 유효성은 보장되지 않는다. 신뢰 경계를 지나는 입력과 저장 데이터에 검증이 필요하다.

가계부 코드에서 보는 형태

if amount <= 0:
    raise ValueError("금액은 0보다 커야 합니다")
한 번 더 들어가기 · 쉬운 풀이와 단어 설명
LEVEL 3 · 중·고등학생 눈높이

“숫자를 적으세요”라는 안내와 “0보다 크게 적으세요”라는 검사는 다르다. -1도 숫자이므로 추가 규칙이 필요하다.

런타임은 프로그램이 실제로 실행되는 때다. 검증을 서비스에 둘지 모델에도 둘지는 책임을 정해 일관되게 적용한다.

문자열 변환과 조건문개발자 설명 열기
LEVEL 2 · 개발자 관점

CLI와 CSV에서 얻은 값은 주로 str이다. int(raw)는 정수 파싱을 수행하며 실패하면 ValueError가 발생한다. 변환 성공 뒤에도 금액 범위 등 도메인 조건을 검사해야 한다. 소수를 int(float(raw))로 잘라 허용하지 않는다.

가계부 코드에서 보는 형태

amount = int(raw)
if amount <= 0:
    raise ValueError("양수 정수를 입력하세요")
한 번 더 들어가기 · 쉬운 풀이와 단어 설명
LEVEL 3 · 중·고등학생 눈높이

입력한 "9000"은 글자다. 계산하려면 숫자 9000으로 바꾼 뒤, 양수인지 한 번 더 확인한다.

파싱은 글자를 정해진 자료형으로 해석하는 일이다. if는 조건이 참일 때만 해당 코드를 실행한다.

raise와 try/except개발자 설명 열기
LEVEL 2 · 개발자 관점

raise는 예외를 발생시켜 정상 흐름을 중단한다. try/except는 지정한 예외를 처리한다. 검증 함수는 문제를 보고하고, 대화형 입력부는 재입력하거나 명령 경계는 오류 코드로 종료한다. 예외 범위를 좁혀 예상하지 못한 버그를 숨기지 않는다.

가계부 코드에서 보는 형태

try:
    amount = int(raw)
except ValueError:
    print("숫자 형식으로 다시 입력하세요")
한 번 더 들어가기 · 쉬운 풀이와 단어 설명
LEVEL 3 · 중·고등학생 눈높이

작업 중 문제가 생겼다는 알림을 보내는 것이 raise, 그 알림을 받아 안내하는 것이 except다.

예외는 처리 중 발생한 특별한 문제 상황이다. except Exception으로 모든 오류를 성공처럼 넘기면 문제를 찾기 어려워진다.

datetime과 실제 날짜개발자 설명 열기
LEVEL 2 · 개발자 관점

date.fromisoformat 또는 datetime.strptime로 달력상 유효성을 확인할 수 있다. 정확히 YYYY-MM-DD만 허용하려면 정규식 등 형식 검사와 파싱을 결합한다. Python 버전에 따라 fromisoformat은 다른 ISO 표기도 허용할 수 있다.

가계부 코드에서 보는 형태

import re
from datetime import date

if not re.fullmatch(r"[0-9]{4}-[0-9]{2}-[0-9]{2}", raw):
    raise ValueError("YYYY-MM-DD로 입력하세요")
value = date.fromisoformat(raw)
한 번 더 들어가기 · 쉬운 풀이와 단어 설명
LEVEL 3 · 중·고등학생 눈높이

2026-02-30은 숫자 배치는 그럴듯해도 달력에 없다. 모양 검사와 실제 날짜 검사를 둘 다 해야 한다.

형식은 글자의 모양, 유효성은 실제로 가능한 값인지다. datetime은 날짜와 시간을 다루는 표준 라이브러리다.

여러 명령에서 검증 재사용개발자 설명 열기
LEVEL 2 · 개발자 관점

add, update, import가 같은 검증 함수를 호출하면 규칙의 분산을 줄인다. 저장 데이터를 읽는 경계도 검증해야 한다. 카테고리 등록 여부처럼 외부 상태가 필요한 검사는 등록 집합을 인자로 받아 결합도를 낮출 수 있다.

가계부 코드에서 보는 형태

def validate_category(name: str, registered: set[str]) -> str:
    if name not in registered:
        raise ValueError("카테고리를 먼저 등록하세요")
    return name
한 번 더 들어가기 · 쉬운 풀이와 단어 설명
LEVEL 3 · 중·고등학생 눈높이

입구가 세 개여도 같은 검사 기준표를 사용한다. 추가할 때는 금액을 검사하고 가져오기에서는 빼먹는 실수를 줄인다.

재사용은 같은 코드를 복사하는 대신 한 함수를 여러 곳에서 부르는 것이다. 카테고리 정규화 규칙은 별도 정책이다.

가계부 코드에서 보는 형태

def handle_errors(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        try:
            return func(*args, **kwargs)
        except ValueError as exc:
            print(f"오류: {exc} / 입력값을 확인하세요", file=sys.stderr)
            return 1
    return wrapper

# 필요한 import: functools.wraps, sys

기능 앞에 공통 안내 직원을 세운다. 정상 작업은 그대로 넘기고, 예상한 문제가 생기면 읽기 쉬운 설명으로 바꿔 알려 준다.

데코레이터는 함수를 감싸 동작을 덧붙이는 도구다. 위 코드에서 감싸는 대상은 정상 시 int를 반환하는 명령 함수로 통일한다.

LEVEL 2 · 개발자 관점

오류 처리 데코레이터는 CLI 명령 경계 한 곳에 적용한다. 서비스와 저장소는 예외를 호출자에게 전파한다. 같은 경로의 안팎을 모두 감싸면 중복 안내나 오류를 성공값으로 오인하는 문제가 생길 수 있다. 제너레이터 순회도 try 범위 안에서 수행해야 한다.

가계부 코드에서 보는 형태

@handle_errors
def handle_list(service, limit) -> int:
    for tx in service.list_transactions(limit):
        print(tx)
    return 0

여러 직원이 똑같은 오류 방송을 반복하지 않고 마지막 사용자 창구 한 곳에서 안내한다. 뒤늦게 읽다가 난 오류도 그 창구가 받아야 한다.

지연 실행은 실제 작업이 나중에 일어나는 성질이다. 제너레이터 객체를 만드는 순간만 감싸면 읽는 도중 발생한 오류를 잡지 못한다.
