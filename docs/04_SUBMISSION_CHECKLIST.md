# 04. 제출 점검표

이 문서는 프로그램 구현 후 사용하는 검증 양식입니다. 현재는 모든 항목이 미검증입니다. 실제 실행 후에만 `[x]`로 바꾸고 결과를 기록하세요.

## 1. 환경과 구조

- [ ] Python 3.10 이상에서 실행된다.
- [ ] 외부 패키지를 설치하지 않고 실행된다.
- [ ] `python -m budget_app --help`가 정상 종료한다.
- [ ] 10개 명령 각각의 `--help`가 동작한다.
- [ ] `budget set`, `category add/list/remove`의 도움말이 동작한다.
- [ ] 클래스가 2개 이상이며 이름과 역할을 설명할 수 있다.
- [ ] 모듈이 3개 이상이며 CLI·서비스·저장·모델 책임이 나뉜다.
- [ ] 모델과 주요 함수에 타입 힌트가 있다.
- [ ] 직접 만든 데코레이터가 실제 실행 경로에 적용되어 있다.

## 2. 샘플 데이터 검증

다음 명령은 구현 완료 후 실행합니다. `verify-data`는 이전 거래가 없는 새 폴더를 사용하세요. 반복 실행하면 import가 중복 추가되므로 새 경로를 사용해야 합니다.

```powershell
python -m budget_app --data-dir ./verify-data import --from examples/transactions.csv
python -m budget_app --data-dir ./verify-data list --limit 2
python -m budget_app --data-dir ./verify-data summary --month 2024-01 --top 3
python -m budget_app --data-dir ./verify-data budget set --month 2024-01 --amount 5000
python -m budget_app --data-dir ./verify-data summary --month 2024-01 --top 3
python -m budget_app --data-dir ./verify-data search --category food -q 점심 --tag lunch
python -m budget_app --data-dir ./verify-data export --out january.csv --month 2024-01
```

| 확인 | 예상값 |
| --- | --- |
| 가져온 건수 | 4 |
| 1월 수입 | 20,000원 |
| 1월 지출 | 6,500원 |
| 1월 잔액 | 13,500원 |
| 분류별 지출 | food 5,000원, transport 1,500원 |
| 예산 5,000원 사용률 | 130.0%, 초과 경고 |
| list limit 2 날짜 | 2024-02-01, 2024-01-15 |
| 식비 + 점심 + lunch 검색 | 1건 |
| 1월 CSV 내보내기 | 3건 + 헤더 |
| 2월 수입 / 지출 / 잔액 | 0원 / 3,000원 / -3,000원 |
| 3월 요약 | 데이터 없음 |

태그와 쉼표가 있는 메모를 포함해 원본 CSV와 내보낸 CSV의 의미가 같은지 확인합니다. 1월 CSV를 다른 새 폴더에 import한 뒤 1월 합계를 비교하세요. ID와 내부 파일 행 순서는 달라도 됩니다.

## 3. 기능별 확인

- [ ] `add`: 모든 필드를 대화형으로 입력하고 저장된 ID를 확인한다.
- [ ] `add`: 두 거래의 ID가 다르다.
- [ ] `list`: 역순 날짜로 입력해도 최신 날짜순이다.
- [ ] `list`: 기본 limit과 `--limit 1`을 확인한다.
- [ ] `search`: 날짜 양 끝 포함, 분류, 종류, 메모, 태그를 각각 확인한다.
- [ ] `search`: 여러 조건을 동시에 적용하고 결과 없음도 확인한다.
- [ ] `summary`: TOP N, 수입만 있는 월, 지출만 있는 월, 빈 월을 확인한다.
- [ ] `budget`: 같은 월 예산을 재설정해 중복 없이 갱신된다.
- [ ] `budget`: 예산과 지출이 같으면 초과 경고가 없고, 더 크면 경고한다.
- [ ] `category`: 새 분류 추가·목록·미사용 분류 삭제가 동작한다.
- [ ] `category`: 중복·빈 이름·사용 중인 분류 삭제를 거부한다.
- [ ] `update`: 한 필드 수정 시 나머지 필드와 ID는 유지된다.
- [ ] `update`: 날짜·종류·분류·금액·메모·태그를 모두 수정할 수 있다.
- [ ] `delete`: 선택한 거래만 삭제된다.
- [ ] `import`: 필수 헤더·양수 금액·날짜·분류 검증이 동작한다.
- [ ] `export`: 월과 기간을 각각 확인하고 처리 건수를 출력한다.
- [ ] 거래·예산·분류가 새 프로세스에서도 유지된다.
- [ ] 기본 data 폴더와 `--data-dir` 지정 폴더가 각각 동작한다.

## 4. 오류와 데이터 보존

수정 전 데이터 파일의 복사본 또는 해시를 남기고 실패 후 비교합니다. 해시는 PowerShell의 `Get-FileHash ./verify-data/transactions.jsonl`로 확인할 수 있습니다.

| 입력·상황 | 기대 결과 |
| --- | --- |
| 금액 `0`, `-1`, `abc`, `1.5` | 원인·해결 힌트, 저장되지 않음 |
| 날짜 `2024-02-30`, 월 `2024-13` | 날짜/월 오류 |
| 종류 `other`, 없는 분류 | 입력 오류 |
| 없는 ID 수정·삭제 | 없는 데이터 안내, 원본 유지 |
| update 수정 옵션 없음 | 사용법 안내, 원본 유지 |
| `--limit 0`, `--top -1` | 범위 오류 |
| 검색 시작일이 종료일보다 늦음 | 기간 오류 |
| export 조건 없음·월과 기간 혼용 | 옵션 조합 오류 |
| CSV 필수 헤더 누락 | 가져오기 실패, 원본 유지 |
| CSV 중간 행의 잘못된 금액 | 전체 실패 정책에 따라 원본 유지 |
| 저장 JSONL의 손상 행 | 파일·행 번호 안내, 재작성하지 않음 |
| 읽기·쓰기 불가 경로 | 경로·권한 안내, 성공 메시지 없음 |

정상 종료 직후 `$LASTEXITCODE`는 0, 오류 직후에는 0이 아닌지 확인합니다. 사용자에게 스택트레이스가 보이지 않아야 합니다. 손상 파일 검증은 실제 기록 대신 별도 검증 폴더에서 진행하세요.

## 5. 스트리밍 확인

- [ ] 파일 입력이 `for line in stream`으로 한 줄씩 처리된다.
- [ ] 목록·검색 경로에서 전체 거래에 `read()`, `readlines()`, `list()`, `sorted()`, `fetchall()`을 사용하지 않는다.
- [ ] 임시 DB는 디스크 파일이며 커서를 한 행씩 순회한다.
- [ ] 대량 거래와 뒤늦게 입력한 과거 날짜에서도 최신순이 유지된다.
- [ ] 조기 종료·예외 후 임시 파일과 DB가 정리된다.

월 요약에서 전체 거래를 저장하지 않고 합계만 누적하는지도 확인합니다. 카테고리별 합계 정렬과 거래 전체 정렬은 구분하세요.
